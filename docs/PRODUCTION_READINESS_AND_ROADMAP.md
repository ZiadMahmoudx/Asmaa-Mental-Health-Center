## 1. ملخص تنفيذي

تم الانتهاء بنجاح من بناء المحركات الأساسية للمنصة (محرك حجز المواعيد، الإقفال الذري لمنع التعارض، تسوية الأرصدة، الحجز بالرصيد الكامل والجزئي، المقاييس النفسية، ومكتب مراجعة المدفوعات).

هذا المستند يحدد **الفجوات المتبقية قبل إطلاق المنصة لجمهور حقيقي**، ومصنفة بحسب درجة خطورتها وأولويتها، ليكون دليلاً شاملاً للمطورين وإدارة العيادة.

## 2. 🔴 أولويات حرجة تكسر النظام (يجب حلها فوراً)

هذه البنود تمثل عيوباً هيكلية ستظهر فور استخدام أشخاص حقيقيين للمنصة:

### ١. غياب مسار "نسيت كلمة المرور" (Forgot Password Flow)
* **المشكلة:** لا يوجد أي مسار برمجياً أو واجهة للمريض أو الطبيب لاسترجاع حسابه إذا نسي كلمة المرور. أول مريض ينسى كلمة المرور يُقفل حسابه نهائياً وتضيع قدرته على الوصول لسجلاته ومواعيده.
* **الوضع الحالي:** جدول `VerificationToken` موجود بالفعل في قاعدة البيانات ومفهرس ولكنه غير مستخدم.
* **الحل المطلوب:** بناء واجهة `/forgot-password` وإرسال رابط/رمز تأكيد، وتحديث كلمة المرور بأمان مع تشفير Argon2id.

### ٢. تقييد المعدل السحابي (Rate Limiting على السيرفرليس)
* **المشكلة:** كود تقييد المعدل الحالي يعتمد على ذاكرة الخادم المحلية (`new Map<string, Bucket>()`). على بيئة Vercel Serverless تتجدد الحاويات باستمرار، مما يصفر العداد تلقائياً ويجعل الحماية ضد تخمين كلمات المرور (Brute Force) شكلية في الإنتاج.
* **الحل المطلوب:** نقل عدادات الـ Rate Limiting لجدول في Neon Postgres أو Redis (Upstash) لضمان مشاركة العداد بين كل الحاويات السحابية.

### ٣. غياب نظام تتبع الأخطاء الحي (Live Error Monitoring / Sentry)
* **المشكلة:** لا توجد أداة مراقبة للأخطاء. جميع أخطاء `console.error` تضيع في سجلات الخادم. إذا تعطل حجز لمريض في وقت متأخر، لن يعلم الفريق التقني إلا بعد شكوى المريض.
* **الحل المطلوب:** دمج **Sentry** لتلقي تنبيهات فورية بأي استثناءات أو أعطال في الإنتاج.

### ٤. وتيرة تشغيل المهام التلقائية (Cron Frequency)
* **المشكلة:** وظيفة مسح الحجوزات المنتهية تعمل مرة يومياً عبر إعداد Vercel الافتراضي، مما يجعل الحجوزات المتروكة تحجز المواعيد لفترات طويلة.
* **الحل المطلوب:** ضبط مشغل خارجي (مثل Cron-job.org أو Vercel Cron Pro) لتشغيل `/api/cron/release-holds` كل ٥ دقائق.

### ٥. استبدال بيانات العيادة الافتراضية ببيانات حقيقية
* **المشكلة:** أرقام فودافون كاش، ومعرف إنستاباي، ورقم واتساب المركز في ملفات الإعداد ما زالت قيماً تجريبية افتراضية وتظهر للمريض في نصوص رسائل الواتساب وصفحة الدفع.
* **الحل المطلوب:** تحديث ملفات البيئة `.env` بالبيانات الرسمية للمركز قبل مشاركة الموقع مع أي عميل أو مريض.

## 3. 🟠 طلبات العميل الصريحة (تحت التخطيط)

ميزات طلبها العميل وتتطلب بنية تحتية جديدة:

### ٦. بنية إرسال البريد الإلكتروني التلقائي (Email Infrastructure)
* إرسال تأكيدات الحجز وموجزات الجلسات للطبيب والمريض عبر الإيميل تلقائياً.
* يتطلب: ربط مزود خدمة (Resend أو SendGrid)، وتوثيق الدومين (SPF / DKIM / DMARC)، وتصميم قوالب HTML للرسائل.

### ٧. توليد روابط زووم تلقائياً (Zoom API Integration)
* إنشاء روابط واجتماعات زووم آلياً لكل جلسة معتمدة دون الحاجة لتدخل الأدمن لكتابة الرابط يدوياً.
* يتطلب: حساب Zoom Pro تجاري، وتفعيل تطبيق Server-to-Server OAuth، وربط مفاتيح الـ API.

### ٨. بوابة الدفع الإلكتروني المباشر (Online Payment Gateway)
* الدفع المباشر بالبطاقات البنكية (Visa / Mastercard / Meeza) بجانب التحويل اليدوي الحالي.
* يتطلب: التعاقد مع بوابة دفع معتمدة في مصر (مثل Paymob أو Fawry) وتفعيل Webhooks لتحديث حالة الحجز آلياً.

## 4. 🟡 الجوانب القانونية والتنظيمية (غير برمجية)

متطلبات قانونية وإجرائية قبل استقبال مرضى حقيقيين:

### ٩. ترخيص مقياس الأرق (ISI - Insomnia Severity Index)
* مقياس ISI محمي بحقوق ملكية فكرية، واستخدامه التجاري على المنصة يتطلب إما ترخيصاً من أصحاب الحقوق أو استبداله بمقياس عام مفتوح المصدر.

### ١٠. سياسة الخصوصية وشروط الاستخدام المستقلة
* روابط الشروط والخصوصية الحالية توجه لصفحة الأسئلة الشائعة `/faq`. المنصات الصحية تتطلب وثيقتين قانونيتين مستقلتين توضحان آلية التعامل مع السجلات الطبية.

### ١١. الامتثال لقانون حماية البيانات الشخصية المصري (رقم ١٥١ لسنة ٢٠٢٠)
* تصنيف البيانات النفسية والطبية كـ "بيانات حساسة" يستوجب صياغة إقرار موافقة صريحة من المريض عند التسجيل، وتحديد مسؤول حماية البيانات.

### ١٢. باقة Vercel التجارية
* شروط باقة Vercel Hobby المجانية تمنع الاستخدام التجاري للشركات والعيادات. عند التشغيل الفعلي وتحصيل أموال يجب الترقية إلى Vercel Pro.

## 5. 🔵 قرارات وسياسات إدارية مطلوبة من العيادة

قرارات تنظيمية يجب أن تحسمها إدارة مركز أسما:

### ١٣. بروتوكول وفريق الاستجابة لتنبيهات الأزمة (Crisis Alert SLA)
* طابور الأمان يرصد حالات الخطورة ومحاولات إيذاء النفس من خلال المقاييس بدقة، لكن قيمته تعتمد على وجود فريق مدرب يراجع التنبيهات ويتدخل سريعاً على مدار الساعة.

### ١٤. سياسة استرداد وإلغاء المريض لنفسه
* عند إلغاء المريض لحجزه بنفسه: الرصيد المستخدم يُسترجع فوراً، لكن هل يُسترد الجزء الكاش المدفوع كرصيد؟ وما هي المهلة الزمنية المسموح بها للإلغاء مع الاسترداد (مثلاً قبل ٢٤ ساعة)؟

### ١٥. صلاحية الرصيد المالي (Credit Expiration)
* هل رصيد المريض المالي الناتج عن الإلغاءات صالح للأبد، أم له فترة صلاحية محددة (مثل ٦ أشهر أو سنة)؟

## 6. ⚪ ميزات مقترحة لتعظيم القيمة التجارية للمنصة

تحسينات ترفع من احترافية المنصة وتجربة المستخدم:

* **لوحة مؤشرات وتقارير مالية للأدمن (Clinic Analytics):** إحصائيات الإيرادات الشهرية، معدلات حضور الجلسات، ونسب إشغال الأطباء والغرف.
* **إشعارات المتصفح اللحظية (Web Push Notifications):** تنبيه الطبيب والمريض قبل موعد الجلسة بـ ١٠ دقائق.
* **تصدير الملف الطبي للمريض (Medical Records PDF):** إمكانية قيام الطبيب أو المريض بتصدير ملخص الجلسات والروشتات كملف PDF رسمي.
* **نظام تقييم الجلسات الحقيقي (Patient Reviews & Feedback):** جمع تقييمات حقيقية من المرضى بعد انتهاء كل جلسة لعرضها في ملفات الأطباء.

## 7. 🚀 دليل التكلفة والنشر الفعلي على Vercel و Neon

### ملخص التكلفة المالية:

| البند | مرحلة الانطلاق (مجانية تقريباً) | مرحلة التوسع والنمو التجاري (Pro) |
| :--- | :--- | :--- |
| **اسم الدومين (`.com`)** | $10 - $15 سنوياً (Namecheap / Cloudflare) | $10 - $15 سنوياً |
| **استضافة Vercel** | $0 (Hobby Tier - 100GB Bandwidth + SSL) | $20 شهرياً (Vercel Pro) |
| **قاعدة بيانات Neon Postgres** | $0 (Free Tier - 0.5 GB Storage + Autoscaling) | $19 شهرياً (Launch Plan - 10 GB + PITR) |
| **تخزين الصور Vercel Blob** | $0 (1 GB مجاناً تكفي آلاف الإيصالات) | $0.15 لكل GB إضافي |
| **الإجمالي المتوقع** | **~$12 سنوياً فقط (ثمن الدومين)** | **~$39 شهرياً + الدومين** |

### خطوات النشر الاحترافي للعميل:
1. شراء الدومين وربطه بـ Vercel عبر DNS Records.
2. ضبط متغيرات البيئة السحابية (`DATABASE_URL`, `APP_URL`, `SESSION_SECRET`, `CRON_SECRET`, `BLOB_READ_WRITE_TOKEN`).
3. توجيه فرع الإنتاج الأساسي في Vercel ليكون `main`.
4. إنشاء أول حساب أدمن عبر الداتابيز للبدء في إدارة العيادة وإضافة الأطباء.
